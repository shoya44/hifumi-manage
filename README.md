# ひふみ 卓上オーダー

藤沢シーシャカフェ&バー「ひふみ」の店舗管理サブシステム（設計ドキュメント類・DBスキーマ・操作プロトタイプ）です。

お客さまが卓のQRコードからスマートフォンで注文し、スタッフがタブレットのダッシュボードで卓の状態・呼び出し・未提供の注文を把握できる仕様の設計資料と、ブラウザで動く操作プロトタイプを含みます。

---

## 現状（リポジトリに実際に含まれるもの）

- `docs/*.pdf` — 設計書（00〜10 の PDF）
- `db/schema.sql` — DDL（スキーマ定義）
- `db/seed.sql` — 初期データ（テーブル座標やメニュー等のサンプルデータ）
- `prototype/index.html` — 単一ファイルの操作プロトタイプ（サーバ不要）
- `seatmap.png` — 店舗の座席レイアウト図
- `menu.txt` — 店舗提供の実メニュー（商品マスタの根拠）

> 注: README の旧版で触れられている `docs/src/`（Markdown ソース）や `docs/build_docs.py`、`frontend/` / `backend/` ディレクトリは、このリポジトリには含まれていません（設計時点の想定や別リポジトリで管理されている可能性があります）。PDF は生成済みの配布物として存在します。

## 使い方（プロトタイプ）

`prototype/index.html` をブラウザで開くだけで、プロトタイプの動作を確認できます（サーバ不要）。

- お客さま画面とスタッフ画面が並んで表示され、片方の操作がもう片方に反映されます。
- `?table=2` を付けると、お客さま専用の全画面表示になります。
- `?vacancy=1` を付けると空席状況の単独公開ページを再現します（このモードでは内部ポーリングを起動しません）。

## 技術構成（注: 実装コードは含まれていません）

設計書では以下のような想定が記載されていますが、現時点では実装用のソース（`frontend/`, `backend/` 等）はリポジトリに含まれていません。

実装コードを配置/管理する予定がある場合は、該当ディレクトリ（`frontend/`, `backend/` など）を追加してください。README は設計と生成物（PDF・プロトタイプ）を優先して正としています。

## セットアップ（設計書に従う箇所）

設計書（`docs/05_開発・運用ガイド.pdf`）の指示に従ってください。リポジトリに含まれるファイルだけでできることは主にプロトタイプの確認とスキーマのレビューです。

簡易手順（プロトタイプ）:

```
# ブラウザで開く
open prototype/index.html
```

簡易手順（スキーマ確認）:

```
# 任意の Postgres 環境で
psql -f db/schema.sql
psql -f db/seed.sql
```
