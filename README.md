# ひふみ 卓上オーダー

藤沢シーシャカフェ&バー「ひふみ」の店舗管理サブシステム。
お客さまが卓のQRコードからスマートフォンで注文し、スタッフがタブレットの
ダッシュボードで卓の状態・呼び出し・未提供の注文を一元的に把握できるようにする。

既存のWebサイト・予約システム・POSレジとは**完全に独立**しており、
既存システムへの改修は一切発生しない。会計は従来どおりレジで行う。

席へのご案内やお会計は自動化しない。QRから受けるのは、炭の交換やドリンクの
おかわりのように**会話が不要な用件**に限り、巡回の手間を減らしたぶんを
ご案内・フレーバーの相談といった会話に振り向けることを狙いとする。

現在は **設計完了 / 試作版によるユーザー確認中** の段階。本実装は未着手。

### ドキュメントのビルド

`docs/src/*.md` を編集し、以下でPDFを再生成する。依存は `reportlab` のみ。
日本語フォントはreportlab同梱のCIDフォントを使うため、追加インストールは不要。

```
pip install reportlab
python docs/build_docs.py          # 全件
python docs/build_docs.py 03 04    # 番号を指定
```

**PDFを直接編集しないこと。** Markdownを正とし、変更履歴は各文書末尾に追記する。

## プロトタイプ

`prototype/index.html` をブラウザで開くだけで動作する(サーバー不要)。
お客さまの画面とスタッフの画面が並んで表示され、片方の操作がもう片方に反映される。

URLに `?table=2` を付けると、お客さま専用の全画面表示になる。

確認できる挙動:

- 用件を選んでのスタッフ呼び出しと、画面上部の呼び出し一覧(経過時間で強調が変化)
- 会計以外の用件を「対応しました」で解除しても卓が使用中のまま残ること
- 注文履歴が「準備中」と「提供済み(会計履歴)」に分かれること
- タブレットからのメニュー価格更新と、**注文済み明細の金額が変わらないこと**
- 画面を非表示にするとポーリングが止まり、復帰時に1回だけ即取得すること
- 未開栓の卓のQRで403、会計クリア後の古い画面でセッション失効になること

## 設計上の不変条件

以下は崩すとセキュリティ事故または業務事故に直結する。
変更前に必ず `docs/src/08_Project_Overview_保守担当者向け.md` 7章を読むこと。

1. フロントエンドにSupabaseクライアント・鍵を持たせない
2. 顧客系APIは必ず `X-Session-Token` を検証する(FastAPIのDepends経由)
3. RLSは全テーブル有効・ポリシー未作成のまま保つ
4. `orders` の部分UNIQUE `(table_id) WHERE status='Active'` を外さない
5. ステータス遷移の妥当性はサーバー側で検証する
6. 価格は注文時点の値を明細にスナップショットする
7. 金額の整形は1箇所(FEは `shared/price.ts`)に集約する
8. `checkout_staff_id` は日次バッチでのクリア時はNULLのまま残す
9. 変動価格の商品は明細の手入力ではなく `products.price` の更新で対応する
10. `products.price` の更新時に `order_items.price` を追随させない
11. 呼び出しの解除と会計クリアを別APIとして分ける
12. ドキュメントの修正は `docs/src/*.md` に対して行う
